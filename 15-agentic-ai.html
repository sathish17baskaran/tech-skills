Agentic AI: from chatbots to autonomous agents

LLMs that plan, use tools, remember and act in a loop toward a goal, plus the protocols (MCP, A2A), patterns and guardrails that make them safe in an enterprise.

15.1 What is Agentic AI?

An AI agent is an LLM that decides its own next steps. It reasons, calls tools, observes the results and repeats until the goal is met.

Chatbotanswers from memory
→
RAG assistantanswers from your docs
→
WorkflowLLM steps in fixed code paths
→
Single agentchooses tools & steps
→
Multi-agent systemagents collaborate
Autonomy, power and risk increase left → right

🧠 Model (brain)

Reasoning and decision-making.

🛠 Tools (hands)

APIs, search, code execution, databases, other agents.

💾 Memory

Conversation state, long-term knowledge, past experiences.

🗺 Planning

Break goals into steps, reflect, re-plan.

🛡 Guardrails

Permissions, limits, approvals, monitoring.

Chatbot vs Agent in one line 🤖

A chatbot tells you how to reset your card PIN.

An agent checks your identity, calls the card API, resets the PIN, confirms by SMS, and asks for approval before anything risky.

Agents = LLM + tools + memory + a loop. With great autonomy comes great need for guardrails.

15.2 Workflows vs Agents (and the 5 workflow patterns) Added

Workflows: LLMs and tools follow paths you coded. Agents: the LLM decides the path. Use the simplest option that works.

1. Prompt chaining

LLM 1
→
check
→
LLM 2

Fixed sequence, e.g. draft → review → translate.

2. Routing

Router
→
A | B | C

Classify, then send to a specialised prompt or model (complaints vs FAQs).

3. Parallelisation

Split
⇉
LLMs
⇉
Merge

Sectioning (subtasks) or voting (several tries for confidence).

4. Orchestrator-workers

Orchestrator
→
workers…

A central LLM plans subtasks dynamically and delegates them.

5. Evaluator-optimiser

Generate
⇄
Critique

Loop until quality criteria are met.

🤖 Agent

LLM
⇄
tools / env

Open-ended loop. Use it when the steps can't be predicted in advance.

  • Workflows are predictable, testable and cheaper. Agents are flexible but cost more and are harder to control. Start with a workflow and add autonomy only where it pays off (Anthropic, "Building effective agents").

// Routing workflow: the code decides the path, the LLM only classifies

{

    Route.Complaint => (await complaintsAgent.RunAsync(message)).Text,
    _               => (await faqAgent.RunAsync(message)).Text
};

15.3 The agent loop (ReAct) Added

ReAct = Reason + Act. Think, act with a tool, observe the result, repeat.

Perceive
→
Reason / plan
→
Act (tool)
→
Observe
↺
until done / limit hit
  • Always set stop conditions: max steps, max tokens or cost, timeouts. Agents can loop forever.
  • Variants: Plan-and-execute (plan everything first, then run it), Reflexion (self-critique after failures).

15.4 Tools & function calling Added

You describe tools with a name, a description and a JSON schema. The LLM replies with a structured tool call. Your code runs it and sends the result back.

  • Good tools: clear names and descriptions, narrow scope, validated inputs, helpful error messages, idempotent where possible.
  • Run tools with the end user's identity (delegated auth), not a super-user service account.
  • Fewer, well-designed tools beat 100 overlapping ones. The model gets confused.
.NET 10 How to implement it
Library / APIPackageUse it for
AIFunctionFactory.CreateMicrosoft.Extensions.AITurn any C# method into a tool. The JSON schema is generated from the parameters and [Description] attributes
ChatOptions.Tools / ToolModeMicrosoft.Extensions.AIOffer tools per request; ChatToolMode.RequireAny forces a call
Delegated identityMicrosoft.Identity.Web (on-behalf-of), IHttpClientFactoryTools call downstream APIs as the end user, not a super-user
Input validationbuilt-in System.ComponentModel.DataAnnotationsValidate tool arguments; return a clear error string the model can act on
public sealed class CardTools(ICardApi cards)
{
    [Description("Gets the status of a customer's card by its last 4 digits.")]
    public async Task<string> GetCardStatus([Description("Last 4 digits of the card")] string last4) =>
        last4.Length == 4 ? await cards.GetStatusAsync(last4) : "Error: last4 must be 4 digits";
}

IChatClient chat = new ChatClientBuilder(inner).UseFunctionInvocation().Build();
var cardTools = new CardTools(cardApi);

var options = new ChatOptions { Tools = [AIFunctionFactory.Create(cardTools.GetCardStatus)] };
ChatResponse reply = await chat.GetResponseAsync("Is my card ending 4821 blocked?", options);

The model only sees names, descriptions and parameter schemas, so write them for the model: clear verbs, narrow scope, few parameters.

15.5 Memory & planning Added

Memory lets an agent keep context within a task and across sessions. Planning lets it break a goal into steps and recover from mistakes.

Short-term (working)

The current conversation and scratchpad in the context window. Summarise or trim as it grows.

Long-term

Stored outside the model (vector DB, key-value store): user preferences, facts, past cases.

Episodic / semantic / procedural

Past experiences · facts about the world · how-to skills and instructions.

State & checkpoints

Persist agent state so long tasks can pause, resume or wait for human approval (e.g. LangGraph checkpoints).

Planning techniques

  • Task decomposition: break the goal into sub-tasks.
  • Chain-of-thought / reasoning models: think step by step before acting.
  • Reflection / self-critique: review the output and fix it.
  • Re-planning: adjust when an observation contradicts the plan.

Long-termA VectorData collection (Microsoft.Extensions.VectorData.Abstractions); Agent Framework context providersStore facts and past cases as embeddings and inject the relevant ones per turn

history.AddMessages(r);

15.6 Multi-agent patterns Added

Several specialised agents work together, like a team with roles.

👔 Supervisor / orchestrator

Supervisor
→
Research · Writer · Checker

A central agent routes work and combines the results.

🏢 Hierarchical

Supervisors of supervisors, for big problems.

🏭 Sequential pipeline

Agent A → B → C, like an assembly line.

🤝 Handoff (swarm)

Agents pass control to each other ("transfer to billing agent").

💬 Group chat / debate

Agents discuss or critique each other to reach a better answer.

  • Frameworks: LangGraph, Microsoft Agent Framework / Semantic Kernel / AutoGen, CrewAI, OpenAI Agents SDK, Google ADK, Azure AI Foundry Agent Service, Amazon Bedrock Agents.
  • More agents means more cost, latency and failure modes. Use multiple agents only when roles really differ.

15.7 MCP & A2A protocols Added

MCP (Model Context Protocol) is a standard way for AI apps to connect to tools and data, "USB-C for AI". A2A (Agent2Agent) is a standard for agents to talk to each other.

Host appIDE, chat, agent
→
MCP client
⇄JSON-RPC (stdio / streamable HTTP)
MCP server: Jira
MCP server: SQL DB
MCP server: Internal APIs

MCP primitives

  • Tools: actions the model can call
  • Resources: data the app can read (files, records)
  • Prompts: reusable templates

Build a connector once, and any MCP-compatible app or agent can use it, instead of N×M custom integrations.

A2A

  • Agents publish an Agent Card (capabilities, endpoint, auth)
  • Agents delegate tasks to each other across vendors and frameworks
  • MCP = agent ↔ tools. A2A = agent ↔ agent
  • Treat MCP servers like any integration: authentication (OAuth), least-privilege scopes, input validation, audit logs, and trusting only vetted servers (tool poisoning is a real risk).

15.8 Guardrails, safety & human-in-the-loop Added

Agents act in the real world, so wrap them in controls before, during and after every step.

Input guardrailsprompt injection · PII · topic filter
→
Agent
→
Tool guardrailsallowlist · least privilege · sandbox · HITL approval
→
Output guardrailsgroundedness · toxicity · schema · PII redaction

Prompt injection

Direct: "ignore previous instructions…". Indirect: hidden instructions inside retrieved web pages, emails or documents. Treat all retrieved content as untrusted data.

Excessive agency

Too many tools or permissions. Scope tools tightly and require approval for money movement, deletions and external communications.

Budgets & limits

Max steps, tokens, cost and time per task. Rate limits on tools.

Audit & explainability

Log every thought, tool call and result for review and compliance.

  • Human-in-the-loop for high-impact actions. Human-on-the-loop (monitoring) for low-risk ones.

}

ApprovalRequiredAIFunction only marks a tool. The agent runtime (Agent Framework) enforces it. If you call IChatClient directly, check approval in your own code. Azure AI Foundry guardrails can also apply Prompt Shields and content filters to a model deployment without code.

15.9 Agent evaluation & AgentOps Added

You test an agent on its trajectory (the steps and tools it used), not just its final answer.

Metrics

  • Task success rate
  • Tool-call accuracy (right tool, right arguments)
  • Steps, latency, cost per task
  • Escalation and human-override rate
  • Safety violations

Practices

  • Scenario test suites + regression runs in CI
  • Tracing every step (OpenTelemetry GenAI conventions)
  • Replay failed runs
  • Version prompts, tools and models

Tools

LangSmith, Langfuse, Arize Phoenix, Azure AI Foundry tracing & evaluation, Weights & Biases Weave.

When to use an agent? Checklist

  • ✅ The steps can't be predicted and need judgement.
  • ✅ The value is high enough to justify the cost and latency.
  • ✅ Tools exist with proper auth, and errors can be recovered from or approved.
  • ❌ Deterministic process? Use a workflow or plain code.
  • ❌ Zero tolerance for error with no human check? Don't automate it with an agent yet.

⚡ Quick-fire Q&A

Difference between RAG and an agent?

RAG is a fixed retrieve-then-generate pipeline. An agent decides dynamically what to do, and retrieval can be one of its tools (agentic RAG).

MCP vs function calling?

Function calling is how a model asks to invoke a tool. MCP is a standard protocol for exposing and discovering tools, resources and prompts from external servers, so tools are reusable across apps.

How do you defend against indirect prompt injection?

Treat retrieved content as data, not instructions. Isolate privileges, scope tools tightly, require approval for sensitive actions, use content filters and injection detection, and monitor tool use.
