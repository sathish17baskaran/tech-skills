💡 Best practices & tips

Best practices
  • LLM basics: treat output as a likely guess, not a fact. Put the facts the model needs in the prompt and verify anything that matters.
  • Tokens and context: budget tokens like money. Long prompts cost more and respond slower, so put key instructions at the start or end.
  • Prompt engineering: give a role, clear rules, 2–3 examples and an output format. Keep prompts in version control like code.
  • Structured output: use the API's JSON or structured-output mode with a schema, and still validate the result in code.
  • Temperature: use 0–0.3 for extraction, classification and JSON; go higher only for creative work.
Learning tips
  • Keep a prompt journal: the prompt, the model, the output and what you changed.
  • Change one thing at a time when you test a prompt.
  • If the 1-hour Karpathy talk feels heavy, do Practice exercises 1–2 first, then come back to it.

💡 Best practices & tips

Best practices
  • Architecture patterns: start with the simplest pattern that works (prompt → RAG → agent → fine-tune) and move up only when evaluation shows you need to.
  • Prompting vs RAG vs fine-tuning: prompting for behaviour, RAG for knowledge that changes, fine-tuning for a consistent style or format, or to run a smaller, cheaper model.
  • Model selection: shortlist 2–3 models, test them on 20–50 real examples, and compare quality, latency and cost per request.
  • AI gateway: put a gateway in front of every model for authentication, quotas, logging, caching and failover.
  • ADRs: write one for every major choice (model, vector database, framework) with the options, the decision and the trade-offs.
  • Open-weight and self-hosted models: prototype with Ollama, but self-host in production only when data rules or volume justify running GPUs yourself.
  • Cost estimation: estimate cost per request and per month for every design option, and add a buffer (for example 30%) for retries, longer prompts and growth.

RAG

RAG Fundamentals

Learn: Document ingestion (parsing PDFs, tables, scanned files), chunking strategies, embeddings, vector databases, similarity search, top-K retrieval, metadata filtering, prompt grounding, citations, permission-aware retrieval (users only see what they're allowed to).

📌 Topics to master this week

RAG overviewRetrieve the relevant pieces of your knowledge, augment the prompt with them, then let the LLM generate a grounded answer with citations.
ChunkingSplit documents into small, meaningful pieces. Each chunk should be precise enough to retrieve and complete enough to answer from.
EmbeddingTurns text (or images) into a list of numbers (a vector), so that similar meaning ends up close together.
Vector searchFind the stored vectors nearest to the query vector. Nearest = most similar in meaning.
Top-K retrievalReturn the K most similar chunks to the query. K controls the trade-off between recall and noise.
Metadata filteringNarrow the search with structured attributes (date, product, region, access level) as well as semantic similarity.

💡 Best practices & tips

Best practices
  • Ingestion: clean documents first (remove headers, footers and duplicates), keep tables as tables, and OCR scanned files.
  • Chunking: start with recursive splitting at roughly 300–800 tokens and 10–20% overlap, split on headings where you can, then tune with evaluation.
  • Embedding: use the same embedding model for documents and queries, and re-embed everything if you change models.
  • Vector search and top-K: start with k = 3–5. Too few misses facts; too many adds noise and cost.
  • Metadata filtering: store source, date, owner and access group on every chunk. Enforce user permissions in retrieval, never in the prompt.
  • Grounding: tell the model to answer only from the context, cite its sources, and say "I don't know" otherwise.
Learning tips
  • Use your own documents; you'll spot bad answers straight away.
  • Print the retrieved chunks for every question. Most RAG bugs are retrieval bugs.

Advanced RAG Architecture & Evaluation

Learn: Hybrid search, ranking and re-ranking, query transformation (rewriting, multi-query, HyDE), RAG Fusion, advanced patterns (GraphRAG, agentic RAG, parent-child chunks), multi-tenant / permission-aware retrieval, RAG evaluation, and common RAG failure points and their fixes.

📌 Topics to master this week

Hybrid searchRun keyword search (BM25: exact terms) and vector search (meaning) together, then fuse the results. You get the best of both.
Ranking & re-rankingFirst-stage retrieval is fast but rough. A re-ranker carefully re-scores the shortlist and puts the truly relevant chunks on top.
Query transformationUsers ask vague, messy or multi-part questions. Rewrite the query into something that retrieves better before you search.
RAG FusionGenerate multiple versions of the user's query, retrieve for each, then fuse all the result lists with Reciprocal Rank Fusion before generating.
RAG evaluationEvaluate retrieval (did we find the right chunks?) and generation (is the answer faithful and useful?) separately. You can't improve what you don't measure.
Advanced RAG patternsVariants that go beyond basic retrieve-then-generate for harder questions and data, such as parent-child chunks, GraphRAG and agentic RAG.
Common failure points & fixesAnswer not found → better parsing, chunking, hybrid search. Wrong answer → re-ranker, smaller K. Outdated → re-index with version filters. Hallucination → "answer only from context" plus citations. Restricted data shown → ACL filters. Slow or costly → caching and fewer chunks.

💡 Best practices & tips

Best practices
  • Prompt injection: assume it will happen. Treat retrieved and tool content as untrusted, and never let model output trigger a sensitive action without checks.
  • Excessive agency: give agents the fewest tools and narrowest permissions, and run them as the user, not as a super-account.
  • Data privacy and leakage: filter PII on the way in and out, keep personal data in approved regions, enforce access control in retrieval, and keep secrets out of system prompts.
  • Guardrails: layer input filters, output filters, tool allow-lists and human approval.
  • Responsible AI: document intended use, limits and owners in a model card, test for bias and harmful output, and keep a named human accountable.
  • AI security and governance: classify every use case by risk tier and map its controls to the NIST AI RMF, ISO/IEC 42001 and local rules.

💡 Best practices & tips

Best practices
  • LLMOps: version prompts, models and evaluation datasets together; every change runs the evaluation set in CI before release.
