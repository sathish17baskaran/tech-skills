Section 21

Cloud cheat sheet: Azure vs AWS vs GCP

The same building blocks exist on every big cloud, under different names. This page maps them side by side: a one-line definition, the current product name on each cloud, what to use it for, and what to remember about security, cost and patterns. Each category also lists the .NET 10 SDK packages for all three clouds.

Service mapping based on ByteByteGo's Compare Cloud cheat sheet (PDF). The definitions, tips and extra rows are our own, and product names were checked against official docs in October 2026. The PDF also has an Oracle Cloud column; this page covers Azure, AWS and GCP only.

21.1 How to read this cheat sheet Added

Four ideas make every row easier to read: who is responsible for what, how each cloud names its locations, how you pay, and how each cloud decides who can do what.

1. Shared responsibility

The cloud always secures the buildings, hardware and hypervisor. The more managed the service, the more the cloud takes on. You always own your data, your identities and access rules, and your configuration.

  • Security: design zones and access first. Use at least 2 zones for production, and give code an identity instead of a password on every cloud.
  • Cost: on-demand for new or spiky load, commitments for the steady baseline, spot for work that can restart. Watch egress.
  • Pattern: map by capability, not by name. "S3 = Blob = Cloud Storage" is useful, but limits, consistency and pricing still differ.

Azure, AWS or GCP? The names change. The building blocks don't ☁️

🧩 Every cloud has compute, storage, networking, databases, messaging, AI and identity

🛡️ Shared responsibility: the more managed the service, the less you patch. Data and access are always yours

💰 On-demand for spiky load, commit for the baseline, spot for restartable work

🌏 GCP VPCs are global. Azure VNets and AWS VPCs are regional

Learn the capability first, then the three names. What surprised you most moving between clouds?

🔄 Renamed / retired (checked Oct 2026)

  • Google Container Registry → Artifact Registry. Container Registry shut down on 18 March 2025. (cloud.google.com)
  • Azure Spring Apps retires on 31 March 2028 and has been closed to new customers since 17 March 2025. Microsoft points to Container Apps or AKS. (learn.microsoft.com)

21.4 Storage: object, block, file & archive Added

Where bytes live. Object storage for files and data lakes, block storage as a VM's disk, file shares for apps that need a drive letter, and archive for records you must keep but rarely read.

Corrected from the PDF: "File Storage" is Azure Files and "File Store" is Filestore. GCP block storage now includes Hyperdisk as well as Persistent Disk.

  • Security: turn off public access at the account or organisation level. Share with short-lived signed URLs: user delegation SAS · S3 presigned URLs · V4 signed URLs.
  • Cost: tiers have minimum storage days and read fees. Moving data out (egress) or reading it back from archive can cost more than storing it.
  • Pattern: keep the lake in one cloud and bring compute to the data. Copying petabytes between clouds is slow and expensive.
  • Encryption: all three encrypt at rest by default. Use customer-managed keys (Key Vault · KMS · Cloud KMS) when policy says you must control the key.

// Same job, three clouds: each SDK finds credentials without a key in code
// Azure: DefaultAzureCredential tries env vars, workload/managed identity, then your dev login
var blobs = new BlobServiceClient(new Uri("https://stbank.blob.core.windows.net"),
    new DefaultAzureCredential());
await blobs.GetBlobContainerClient("statements")
    .UploadBlobAsync("2026-10/acc-42.pdf", BinaryData.FromBytes(pdf));

// AWS: the default credential chain finds env vars, profile/SSO, or the IAM role
var s3 = new AmazonS3Client(RegionEndpoint.APSoutheast2);
await s3.PutObjectAsync(new PutObjectRequest
    { BucketName = "bank-statements", Key = "2026-10/acc-42.pdf", InputStream = new MemoryStream(pdf) });

// GCP: Application Default Credentials (attached service account, or gcloud login on dev)
var gcs = await StorageClient.CreateAsync();
await gcs.UploadObjectAsync("bank-statements", "2026-10/acc-42.pdf", "application/pdf", new MemoryStream(pdf));

Storing data in the cloud is cheap. Getting it back out isn't 💸

🧊 Hot → cool → cold → archive tiers cut storage cost as data ages

⏳ But every colder tier has a minimum stay (archive: 180 days on Azure and AWS, 365 on GCP)

📤 Egress and archive reads are billed per GB. A "cheap" archive can get expensive on restore day

🔐 Block public access everywhere, and share with short-lived signed URLs

Model the read path, not just the write path. How often do you really restore?

21.13 Choosing a cloud (or multi-cloud) Added

Most organisations pick one primary cloud, add a second for specific strengths or regulation, and keep some systems on-prem. Choose on skills, services, compliance and commercials, then build a landing zone before the first workload.

Decision factors

🧑‍💻 Skills & ecosystem

A Microsoft shop (.NET, Microsoft 365, Entra ID) often lands on Azure. All three run .NET 10 well, so skills matter more than language.

🌏 Regions & residency

All three have Sydney and Melbourne regions; Azure also has Canberra. Check that every service you need exists in-region.

🧩 Key services

Pick on the services that set you apart (data, AI, mainframe integration). Commodity compute and storage are similar everywhere.

🛡️ Compliance

Check IRAP assessments for the services you'll use. Banks must meet APRA CPS 234 (information security) and CPS 230 (operational risk, material service providers).

💰 Commercials

Enterprise commit discounts, credits, support plans and licence reuse (Azure Hybrid Benefit for Windows Server and SQL Server).

🚪 Exit & lock-in

Data gravity and egress fees are the real lock-in. Containers, PostgreSQL, Kafka, OpenTelemetry and Terraform keep options open.

⚡ Quick-fire Q&A

What's the biggest networking difference between the three clouds?

A GCP VPC is global, with regional subnets, so one network can span regions. Azure VNets and AWS VPCs are regional, so multi-region designs need peering or a hub (Virtual WAN, Transit Gateway).

How does an app call cloud APIs without storing a secret?

It uses the platform's workload identity: a managed identity on Azure, an IAM role on AWS, an attached service account on GCP. The SDK gets a short-lived token from a local endpoint. CI systems use OIDC federation the same way.

Reservations vs savings plans vs committed use discounts?

All trade a 1- or 3-year commitment for a lower price. Reservations and resource-based CUDs lock to a resource type and region. Savings plans and spend-based CUDs commit to an hourly spend and are more flexible. Commit only to your proven steady baseline.

What is the AWS or GCP equivalent of Azure Service Bus?

There is no exact twin. On AWS: SQS (FIFO for ordering) plus SNS for topics, or Amazon MQ if you need AMQP/JMS. On GCP: Pub/Sub with ordering keys and dead-letter topics, or Cloud Tasks for simple work queues. Check sessions, transactions and ordering needs.

Which old service names should you stop using in interviews?

Azure AD (now Microsoft Entra ID), Azure Cognitive Services (Foundry Tools), Azure AI Foundry (Microsoft Foundry), Vertex AI (Gemini Enterprise Agent Platform), Cloud Functions (Cloud Run functions), Container Registry (Artifact Registry), Dataproc (Managed Service for Apache Spark) and Deployment Manager (retired; use Infrastructure Manager or Terraform).

Why is egress so important in multi-cloud designs?

Data going into a cloud is mostly free, but data leaving it is billed per GB. An app in one cloud that reads a database in another pays on every call and adds latency. Keep each workload and its data in the same cloud and region.
